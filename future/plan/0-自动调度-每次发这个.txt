四、判断顺序（每执行完一项重新从第 0 条判断）
0. `future/docs/research/SETUP_DONE.md` 不存在或第一行不是 `结论：DONE` → 执行 00-一次性准备；
   它未完成时停止，不执行后面任何一项。
1. ledger.yaml 不存在或 yaml 解析失败 → 执行 00-一次性准备（重建总账并核对 round 文档）。
2. 存在 candidates 中 final=pending_final 的候选，且其 final_window 的 status=unused
   且当前日期 ≥ 窗口 end → 执行 2-最终检验。
   注意：窗口数据在冻结前不得下载/查看；若已有该窗口数据文件，先报告异常再继续。
3. 存在 rounds[].status ∈ {pending, researching} 且 trials_used < global_trial_budget
   → 执行 1-研究循环（按其规定一次会话最多 3 轮）。
4. 所有 rounds 都是 failed/exhausted、candidates 为空：

5. stage=frozen 且候选 final=pass → 停止并报告"等使用者决定是否实盘"（AI 不得启动任何实盘流程）。
6. 以上都不满足 → 停止，并说明卡在哪个 blocker。

五、前置复核（选中一项后、真正执行前必做，结论写 future/docs/research/review_log.md，只追加）
1. 执行 1 之前：
   - 测试全绿；
   - 上一轮 rounds/<id>.md 的数字与 artifacts/backtest/<run>/metrics.json 一致；
   - ledger 的 trials_used 等于各轮 trials 之和；
   - 本轮已在 rounds/<id>.md 预登记（判据与 ledger.acceptance 一致），未登记不得开跑；
   - 研究期脚本没有读取 2024-07-01 之后的数据（grep 日期常量 + 检查 fetch 的 start/end 参数）。
2. 执行 2 之前：
   - 候选冻结文件 SHA256 与 ledger 记录一致；
   - final_windows 中该窗口 status=unused；
   - scripts/final_run.py 存在，且只有它能读窗口区间；
   - 研究期代码未 import final_run（grep 验证）。
3. 发现问题时：
   a) 文档数字与原始输出不一致 → 以原始输出为准修文档，ledger 同步；
   b) 代码不符合指令规定 → 在 review_log.md 记缺陷（D2、D3…，状态 OPEN），先写能复现的测试，
      再修代码，修好后改 CLOSED 并写提交哈希；
   c) 缺陷影响已作出的判定 → 该轮判定作废（ledger 里把 status 改回 pending 并在 result 里写
      "作废：<缺陷号>"），重跑；已 pass/fail 的最终检验窗口不得重跑；
   d) 无法核实 → 记"无法核实"，跳过该步，继续判断其他项；
   e) 同一缺陷 3 次修不好 → 记 BLOCKED 并停止。
