## 3. 由实测推出的规则修正（需回填 §7.1、§7.3、§8.7）

1. **日线 datetime 是交易日 00:00**，且同一根日线已包含前一自然日 21:00 起的夜盘。
   - 推论 A：`trade_date = tafunc.time_to_datetime(datetime).date()`，无需处理"夜盘起点"。
   - 推论 B：`iloc[-1]` 在 21:00 之后指向的是 **t+1 的未完成柱**（`datetime` 已是 t+1 的 00:00），
     所以"信号只用 ≤ t 的完整日线"必须实现为 **按 `trade_date` 取行**，不能用位置索引（评审 R-06）。
   - 推论 C：F6"t 日信号不含 t+1 夜盘"天然满足——只要 `trade_date <= t`。
2. **占位行必须过滤**：已下市合约序列左端存在 `datetime == 0`（1970-01-01 08:00）的行，
   入库前丢弃，否则 `P` 会从 1970 起累计。
3. **无成交日**：行存在、`close = NaN`、`volume = 0`、`close_oi` 有值。
   - 质量检查改为：`close` 为 NaN 的行标记为"无成交"，参与 `close_oi` 与成交量统计，
     **不参与**价格类特征与收益计算（前向填充只在连续收益里用前一个有效收盘）。
   - 就绪判定（§8.7 第 4 条）改为"执行合约最新 `trade_date == t` 且 `volume > 0`"。
4. **夜盘判定仍需自算**：`get_trading_calendar` 只返回 `date` + `trading`，
   没有 `has_night`；`query_symbol_info.trading_time_night` 只反映当前权限。
   - 结论：`has_night(t) = (td(t) − td(t−1) 的自然日间隔 == 1)`，
     与 `holiday.long_gap_days` 解耦（评审 R-05）。
5. **费率口径分两类**：`margin` 只能当"当前每手金额"用；`commission` 需按品种判定
   （元/手 vs 成交额比例）。`data/rates/fees.yaml` 必须带 `fee_type` 字段，
   并在研究第一轮开始前用交割单核实 `broker_fee_mult`。
